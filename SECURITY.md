# Security and Governance Architecture

## 1. Provenance Guarantees
Every forecast generated by FUTURIS is cryptographically and temporally anchored:
- **Immutable Evidence Snapshots**: Input telemetry slices on or before `as_of` are frozen to disk as Parquet files.
- **Content Hashes**: Each evidence snapshot produces a SHA-256 digest recorded on the `EvidenceRef` entity.
- **Temporal Verification**: The system guarantees $T_{\text{snapshot}} \le T_{\text{as\_of}} < T_{\text{expires\_at}}$.

## 2. Prediction vs Authorization Boundary
FUTURIS strictly maintains that **prediction is not authorization**:
- Numerical forecasts, event probabilities, and confidence intervals are computed deterministically.
- Advisory action recommendations explicitly declare `requires_approval=True`.
- The engine will never trigger scaling, circuit breaking, or mitigation actions autonomously without human or downstream orchestration approval.

## 3. Model Governance & Promotion Gate
Statistical model adapters must pass strict non-inferiority validation before serving traffic:
- **Freshness**: Promotion requires benchmark evaluation runs no older than 30 days.
- **Performance Non-Inferiority**: A candidate adapter cannot have worse Mean Absolute Error ($MAE$) or Expected Calibration Error ($ECE$) than the active model in its family.
- **Audit Logging**: Successful promotions emit `model_promoted` domain events.

## 4. Role-Based Access Control (RBAC) & Audit Trail
- **Viewer**: Read-only access to `/v1/forecasts`, `/v1/evaluation`, and `/ui`.
- **Analyst**: Create forecasts, execute counterfactual scenarios, run backtests, and perform manual ground-truth resolutions.
- **Admin**: System governance, API key management, model promotions, and audit log inspection (`GET /v1/audit`).
- **Append-Only Audit Log**: Every mutating API action logs the actor identity, action type, entity identifier, and SHA-256 payload hash.
